# jccash — app structure

## What it is

Offline exchange budget tracker. Single-page React app, no backend, no login. All state lives in `localStorage`. Designed for mobile first (used on phone during exchange semester) but runs fine in any browser.

## Deployment target

**Netlify** — static/SSR hosting via TanStack Start's built output.

- Access via Netlify URL from phone browser (no app store, no install)
- Fully usable offline once cached — no API calls, no auth
- Phone-friendly: fixed bottom nav, large tap targets, `min-h-dvh` layout

Netlify build command: `bun run build`
Publish directory: `dist/client` (Vite client build + post-build `scripts/generate-index.mjs` which SSR-renders `/` and writes `index.html`)

## Tech stack

| Layer | Tool |
| --- | --- |
| Framework | TanStack Start (React SSR/SPA wrapper) |
| Routing | TanStack Router — file-based, `src/routes/` |
| UI components | shadcn/ui (new-york style) — Radix UI + Tailwind |
| Styling | Tailwind CSS v4 |
| State | Custom `useStore` hook — `useState` + `localStorage` (no external state library) |
| Icons | Lucide React |
| Charts | Conic-gradient (hand-rolled, no chart library) |
| Runtime | Bun |
| Build | Vite 8 + TanStack Start plugin + nitro |
| Type checking | TypeScript strict |
| Testing | Vitest + Testing Library |
| Linting / formatting | ESLint + Prettier |

## Build tooling files

**`bun.lock`** — Bun's lockfile, equivalent to `package-lock.json`. Committed to pin exact versions.

**`bunfig.toml`** — Bun install config. Currently just enables `saveTextLockfile` (human-readable lockfile) and a 24h supply-chain guard that skips packages published less than a day ago.

**`vite.config.ts`** — Vite config. Uses `@tanstack/react-start/plugin/vite` (TanStack Start plugin), `@vitejs/plugin-react`, `@tailwindcss/vite`, and `vite-tsconfig-paths` (resolves the `@/*` alias from tsconfig). Outputs client bundle to `dist/client/`, server bundle to `dist/server/`.

**`scripts/generate-index.mjs`** — Post-build script run by `bun run build`. Imports the built `dist/server/server.js` handler, calls it with a `GET /` request, and writes the SSR HTML response to `dist/client/index.html`. Netlify then serves `dist/client/` as a static site with that HTML as the entry point.

**`tsconfig.json`** — TypeScript config. `@/*` maps to `src/*`. Strict mode on.

**`components.json`** — shadcn/ui config. Points to `src/styles.css` for Tailwind, `@/components/ui` for component output, `lucide` for icons.

**`vitest.config.ts`** — Vitest config, separate from vite.config.ts. Uses jsdom environment.

**`eslint.config.js`** — ESLint flat config with react-hooks and react-refresh rules.

**`.prettierrc`** / **`.prettierignore`** — Prettier formatting config.

## State model (store.ts)

All state is one `State` object, persisted to `localStorage` under the key `jccash-v1`.

```
State
├── budgetSgd       total trip budget in SGD
├── start / end     trip date range (drives "days left" calc)
├── currency        active local currency code (e.g. "EUR")
├── rate            1 local = rate SGD (user-set, no API)
├── cashWithdrawn   how much cash was taken out (local currency)
├── trips[]         trip tags (default: "Daily life")
├── activeTrip      selected trip tag for new expenses
├── expenses[]      log: amount, currency, rate, category, method, trip, date, note
├── splits[]        IOUs: name, amount (SGD), note, paid
└── recurring[]     monthly auto-adds: label, amount, category, lastAdded
```

`stats()` derives everything shown on the home screen (spent, left, perDay, todayLeft, cashLeft) from `State` — no extra stored fields.
